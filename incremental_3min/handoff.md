# handoff.md - 3分ねこクリッカー 引き継ぎ資料 (v20)

v10までの資料は追記を重ねた結果、古い数値（50体ごとのクリック強化、「すぐ移動」メニュー等）と
現在の仕様が混在していました。v11で**現在のコードに合わせて全面的に書き直しています**。
バージョンごとの変更履歴は README.md の「vN変更メモ」を参照してください。

---

## 1. プロジェクトの目的

ブラウザだけで遊べる「3分制限のインクリメンタルゲーム」です。

長時間放置型ではなく、**3分の中でクリック・施設購入・アップグレード購入をどう組み合わせて
累計スコアを伸ばすか**が遊びの中心です。Cookie Clicker系の考え方
（手動クリック / 自動生産施設 / 指数的な価格上昇 / 条件解禁のアップグレード）を参考に、
3分で成立するよう価格・生産量・解禁タイミングを独自調整しています。

**成果物は原則 ZIP形式 + handoff.md で渡してください。**

**利用シーン（v18で判明）**: 展示会に設置するミニゲーム集のひとつ。1台のPCで、毎回ちがう人が交代で遊ぶ。
そのため、結果の持ち帰りは「スマホで撮影」前提（コピー機能などは不要）。
プレイヤーごとの案内（まとめ買いの案内など）は、プレイ開始ごとにリセットすること。

## 2. 守るべきユーザー要望（重要）

1. 制限時間は3分（開始ボタン → 3・2・1・GO! の演出後に180秒スタート）。
2. 左側の猫・ポイント・タイマーは、ショップをスクロールしても常に見える。
3. PCではページ全体をスクロールせず、右側ショップだけがスクロール。
4. 「施設」と「アップグレード」は完全に別タブ。
5. 最初の施設「ねこバイト」は15秒に1回、1体につき1クリックしてくれる。
6. ねこバイトの所持数（20 / 40 / 70体）でクリック強化が順番に解禁。
7. 画像はすべてユーザー提供の猫画像 `assets/cat.png` 1枚を共用。
8. 配色は猫画像のベージュ・茶・くすみピンクが基調。
9. フォントとUIは、あえて少しダサく、カジュアルで親しみやすい方向。
10. JavaScriptには初学者向けの日本語コメントを多く残す。
11. プレイ中は累計スコアより「いま使えるポイント」を大きく表示。
12. 数字は省略しない（M / B 表記なし）。改行もさせず、桁が多い時は文字を縮めて1行に収める。
13. ランキング: 完走したプレイだけを直近10回保存し、その中のTOP5を表示。5位以内でランクイン演出。
14. プレイ中はランキングを隠す（待機中・結果画面で表示）。
15. アップグレードタブの赤い「!」は「新しく解禁された未確認のもの」がある時だけ。
16. 購入済みアップグレードは一覧から消す。
17. まとめ買いは 1 / 最大10個 / MAX。10個モードは足りなければ買えるだけ買う。
    アップグレードタブではまとめ買いUIを隠す。
18. 新しいプレイは必ず「施設タブ + まとめ買い1個 + ショップ先頭」から始める。
19. プレイ途中のリセット（やり直し）ボタンは置かない。終了後の「もう1回やる」のみ。
23. ねこバイトが後半に化けること、まとめ買いがあることに初見でも気づける導線を置く（v18）。
24. 結果画面は「スマホで撮って自慢しよう」。PCでは1画面に収める（v18）。
25. 結果画面のまま60秒操作がなければ待機画面へ自動で戻る（v19）。
26. スペース / Enter でも猫を押せることを、PCでは画面上で案内する（v19）。
27. ねこNEWSはヒントに偏らせず、ネタを多めに。出来事は割り込まず次の1本として流す（v20）。
22. 「ねこNEWS」で、連打より施設投資が伸びることを自然に伝える（v14）。
    説教くさくしないよう、ヒントはニュースの見出し風にし、ネタニュースも混ぜる。
21. 施設は段階的に公開（v13）。アップグレードも条件の3割に達するまで隠す。
20. 最初に開始するまでは待機画面: タイトル・猫・大きな開始ボタン・ねこランキングのみ。
    ショップやポイント表示は丸ごと隠す（猫は「始まったらここを押す」主役として見せる）。

### 施設の段階的公開（v13）

- 累計スコアが `baseCost × FACILITY_REVEAL_RATIO(0.4)` に届くと正体判明（`state.revealedFacilities`）。
- 判明していない施設のうち**最初の1つだけ**を `.mystery`（「？？？」+ 黒シルエット）で予告し、それ以降は `.facility-hidden` で非表示。
- 判明した瞬間は `.just-revealed` で「NEW!」札を3秒表示。
- 配列の先頭（ねこバイト）は最初から判明済み。

### 施設の追加

`FACILITIES` にオブジェクトを1つ足すだけで、カード・価格・まとめ買いが自動対応します。

```js

  name: '超ねこ工場',
  baseCost: 300000,
  costGrowth: DEFAULT_COST_GROWTH,
  mode: 'cps',
  baseCps: 8000,
```

### 解禁条件は `progress` 1つで書く（v11）

v11から、解禁条件は `progress(state)` が返す `[いまの値, 目標値]` で表します。
この1つから「解禁したか（いま >= 目標）」と「ゲージ・12 / 20 表示」の両方を作ります。
よく使う条件には補助関数があります。

```js
progress: needHelpers(20),              // ねこバイト20体
progress: needFacility('cafe', 10),     // ねこカフェ10個
progress: needTotalFacilities(60),      // 施設合計60個
progress: needContinuousCps(2000),      // 通常施設CPS 2,000/秒
```

追加例:

```js
{
  id: 'space_10',
  name: '宇宙ねこアンテナ',
  cost: 500000,
  unlockText: 'ねこ宇宙センターを10個所有',
  progress: needFacility('space', 10),
  description: 'ねこ宇宙センターの生産量を2倍。',
  apply: (state) => { state.facilityMultipliers.space *= 2; },
},
```

旧形式の `unlock: (state) => true/false` も動きます（その場合ゲージは0%か100%のみ）。

未解禁のものは、条件の進み具合が `UPGRADE_PREVIEW_RATIO(0.3)` 以上になるまで `.upgrade-hidden` で隠します。
隠れている件数は一覧の下の `#upgradeEmpty` に「まだ眠っている」として表示します。

一覧の並び順は自動です（今買える → 解禁済み → 未解禁、同じグループ内は安い順）。
配列の順番を気にする必要はありません。

## 6. 数値の仕組み

### ポイントとスコア

- `state.currency` … いま使えるポイント。購入で減る。
- `state.totalProduced` … 累計獲得量。購入で減らない。**3分終了時のスコア**。

「終了時の手持ち」をスコアにすると最後に買い物をしない方が有利になり、
成長行動とスコア行動が衝突するため分けています。加算は必ず `addPoints()` を通してください。

### クリック力

```text
1クリック = 基本1 × clickMultiplier + 通常施設CPS × clickCpsPercent
```

マウス系アップグレードの基準CPSは「ねこバイトを除く通常施設」だけです（循環計算の防止）。
ねこバイトは強化後のクリック力を使うので間接的に恩恵を受けます。

### ねこバイト

15秒ごとに `所持数 × クリック力 × ねこバイト倍率 × 全体倍率` をまとめて加算します（15秒ごとにドンと増える仕様）。

- 発動タイミングは**ゲーム開始からの共通の時計**（0:15, 0:30 … 3:00 の計12回）。買った時刻から数えるのではないので、
  2:59に雇ったねこバイトも3:00の最後の発動に参加する。
- v16: `state.startedAt`（開始時刻）と `state.helperPulsesDone`（発動済み回数）を持ち、毎フレーム
  `floor((今 - 開始時刻) / 15000)` で発動すべき回数を計算し直す。
  v15までは小数の経過秒を足し続ける方式で、誤差により3:00の発動が約半分のプレイで消えていた。
  **経過時間を小数の足し算で数える書き方には戻さないこと。**
画面の「自動生産 /秒」にはこれを15で割った値を足して表示しています。

### まとめ買い

表示と購入は同じ関数 `getPurchasePlan(facility)` を使うため、ズレません。
- 1: 1個
- 10: 最大10個まで、買えるだけ
- MAX: 買えるだけ（安全上限10000）

### 「元が取れるまで 約○秒」と「いまおトク！」（v18, v19で表記変更）

`getFacilityPaybackSeconds(facility)` = 次の1個の値段 ÷ その1個が増やす毎秒生産量。
ねこバイトは15秒ごとの発動量を1秒あたりに直して比べる（クリック力にマウス系強化が乗るので、後半に急に短くなる）。
3分を超える値は「元が取れるまで 3分以上」と表示。一番短い施設（判明済み2種類以上の時）に `.is-best`「いまおトク！」札。
※ スコアは使っても減らないので「元が取れない＝買うと損」ではない。あくまで施設同士の比較用。

### ねこバイト発動バッジ（v18）

`playHelperPulse()` が「バイト○匹 一斉クリック！ / +発動量 / 自動生産の○秒分！」を表示。
自動生産の20秒分以上で `.mega`（黄色・大きく・震える）。

### まとめ買いの案内（v18, script.js 17-2章）

「×1 買う」を4秒以内に5回 → `.bulk-controls.nudge`（10/MAXが光って揺れる）+ `#bulkHint` + ねこNEWSに予約。
一度でも10/MAXを選ぶと `hasUsedBulk` で以後出さない。再表示まで15秒。`startGame()` で毎回リセット。

### 「放置で あと○秒」

`getWaitText(cost)` = 不足分 ÷ 表示上の自動生産量。クリック分は含まない目安です。
残り時間より長ければ「時間内はきびしい」、自動生産0なら「猫を連打！」。

### タイマー

`requestAnimationFrame` + `performance.now()`。終了予定時刻 `state.endAt` から残り時間を逆算します。
タブが裏にある間もゲーム内時間は進み、戻った時にまとめて処理されます。

## 7. 入力まわり（v11）

- マウス・タッチは `pointerdown`（押した瞬間）で1クリック。複数の指も個別に数える。
- キーボード（Enter / Space）は `click` のうち `event.detail === 0` のものだけ処理。
  これでマウスの click と二重に数えません。
- Enter押しっぱなしのキーリピートは `keydown` で無効化（自動連打防止）。
- 猫ボタンは長押しメニュー・ダブルタップ拡大を抑止。
- 結果画面の「もう1回やる」は表示から0.9秒押せない（終了直前の連打による誤爆防止）。

---

### v19 の入力変更

- スペース / Enter は `document` の keydown（capture）で拾い、プレイ中は**どこにフォーカスがあっても猫を押す**。
  ブラウザ標準の動作（フォーカス中のボタンを押す・スクロール）は止める。キーリピートは無視。
- 猫ボタンの `click`（event.detail===0）経由のキーボード処理は廃止（二重カウント防止）。
- キー操作の案内（`.key-hint`）は `(hover: hover) and (pointer: fine)` の端末だけ。JSでは `isKeyboardDevice()`。
- 結果画面で「もう1回やる」には自動フォーカスしない（スペース連打で撮影前に次が始まる事故の防止）。

## 8. 表示の軽量化（v11）

`updateDisplay()` は約50msごとに呼ばれます。v11では:

- カード内の要素は生成時に `facilityRefs` / `upgradeRefs` に保存し、毎回探さない。
- `setText(el, text)` で、文字が変わった時だけ書き換える。
- 「1行に収める」対象は `markFit(el, 最大px, スマホ最大px)` で登録。
  文字が変わった要素だけを比率計算で縮める。非表示中の要素は表示されるまで保留。
- 画面リサイズ時は80ms待ってから全部を測り直す。

新しく「長くなりうる数字」を追加する時は `markFit()` を呼んでください。

## 8.5 ねこNEWS（流れるTIPS, v14）

- 場所（v15で移動）: 左列 `.cat-stage` の中、猫ボタンと現在値 `.live-stats` の間の `#newsTicker`。
  v14ではショップ上部に置いていたが、プレイ中の視線は猫に集まるため猫の真下へ移した。
  - PC: `.cat-stage` は flex 縦並び（猫 → ニュース → 現在値）。猫の幅は `calc((100cqh - 116px) * 4 / 3)` で、
    116px はニュース(約40px)+現在値(約70px)ぶん。ニュースや現在値の高さを変えたらここも直す。
  - スマホ: `.cat-stage` は2列グリッド。1行目「猫 | 現在値」、2行目にニュースを横いっぱい（`grid-column: 1 / -1`）。
    HTMLの並びが猫→ニュース→現在値なので、`.live-stats` は `grid-row: 1; grid-column: 2` で明示配置している。
  - 待機画面（`body.is-idle`）では非表示。
- コード: script.js の「18. ねこニュース」。
- ニュースの種類:
  - `SITUATION_NEWS` … `{ id, when(), text() }`。`when()` が true の時だけ候補。`text()` は流す直前に作るので数字は最新。黄色文字。
  - `TIP_NEWS` … 常に正しい基本ヒント（文字列）。
  - `FLAVOR_NEWS` … ネタ（約30種）。`{ text, needs?, when? }`。`needs: 'box'` はその施設を1個以上持っている時だけ。
    `text` は文字列か関数（数字入りのネタ用）。**施設のネタを足す時は必ず needs を付ける**（未購入の施設のネタが流れないように）。
  - 出来事（v20） … `FACILITIES[].news`（初めて1個買った時）と `UPGRADES[].news`（購入時）の見出し。ピンク文字。
    `queueNewsEvent(text)` で「次に流す1本」として予約するだけで、今のニュースは止めない。
- 選び方 `pickNews()`（v20）:
  1. 予約された出来事があれば優先。ただし出来事を2本続けない。予約は最新2件まで、25秒以上前は捨てる。
  2. ヒント系（状況・豆知識）が2本続いたら、次は必ずネタ。
  3. それ以外は おおよそ ネタ45% / 状況ヒント40% / 豆知識15%。
  4. 直近5本と同じものは避ける。
- 流し方 `playNews()`: Web Animations API で右端→左端の外まで一定速度（`NEWS_SPEED_PX_PER_SECOND` = 110）。流れ終わったら次を選ぶ。
- **ニュースを強制的に切り替える（割り込む）処理は置かない**（v20でくどいと判断）。
- 開始ボタンで `startNews()`（1本目は固定の案内）、終了で `stopNews()`。
- 連打判定は実際のクリック回数から計算（1秒3回以上で「連打している」）。
- ヒントの追加は配列に1行足すだけ。条件関数が例外を出してもニュース全体は止まらない（`safeWhen`）。

## 8.6 展示会向けの自動リセット（v19, script.js 20-2章）

- 結果画面を出した時に `startAutoReturn()`。`AUTO_RETURN_SECONDS`（60）秒操作がなければ `returnToTitle()` で待機画面へ。
- pointerdown / keydown / wheel / touchstart があればカウントをやり直し。
- 「もう1回やる」を押した時は `stopAutoReturn()`。
- `returnToTitle()` は state を初期化し、`body.is-idle` を付け直して、ショップ表示も初期状態に戻す。

## 8.7 アップグレードタブの強調（v19）

## 10. レスポンシブ方針

- **PC（901px以上）**: 左固定・右だけスクロール。猫のサイズは `.cat-stage` の
  `container-type: size` を使い、枠の高さから4:3で逆算（`100cqh`）。低い画面でもはみ出さない。
- **低いPC（高さ760px以下）**: 左を圧縮し、ランキングはショップ側 `.responsive-ranking-panel` へ退避。
- **スマホ（900px以下）**: 上部を「ゲームドック」として sticky 固定。
  高さは `--mobile-game-dock` 1つで管理し、`.play-column` の高さと `.shop-toolbar` の `top` の両方で使う。
  猫と現在値を横並びにして高さを節約。
- **横向き・背の低いスマホ**: 現在値を「ラベル左 / 数字右」の1行にし、「ねこをクリック！」札は隠す。
- プレイ中は `body.playing-session` が付き、開始ボタン・ランキング・注意書きが消えて猫が大きくなる。
- **待機画面**: `<body class="is-idle">` の状態で読み込まれ、`startGame()` で外れる（二度と付かない）。
  CSSは style.css の「11. 待機画面」にまとまっています。ここではスマホ用の sticky ドックや
  「猫 | 現在値」の2列を解除し、1列中央寄せにしています。高さ460px以下ではランキングも隠します。

確認推奨サイズ: 360×640 / 390×844 / 667×375 / 768×1024 / 1366×768 / 1000×500 / 1920×1080

## 14. テスト項目

### タイマー
- 開始前は03:00.0 / 3・2・1・GO! の後に減り始める / 00:00.0で終了
- 終了後に生産が続かない / 残り10秒でタイマーが点滅

### クリック
- 開始前は押せない / マウス1回・タップ1回・Enter1回・Space1回でそれぞれ1クリック
- Enter押しっぱなしで連打にならない
- クリックで所持ポイントと累計スコアが増え、購入では所持ポイントだけ減る

### ねこバイト
- 15秒ごとに発動し、肉球おてて4つが順番にタップ
- 3分間でちょうど12回発動する（3:00ちょうどの発動も入る）
- 獲得量 = 所持数 × クリック力 × 個別倍率 × 全体倍率

### 施設
- 各カードに「元取り 約○秒」、一番早い施設に「いまおトク！」
- 「×1 買う」を素早く5回押すと、まとめ買いの案内が出る。10/MAXを使うと以後出ない
- 開始時は「ねこバイト」と「？？？」1枚だけ。累計スコアに応じて順に正体判明、NEW!札が出る
- 1 / 最大10 / MAX で購入できる。10個モードで資金不足なら買える分だけ
- 買えない時に「放置で あと○秒」が出る

### アップグレード
- 未解禁は買えず、ゲージと「現在 / 目標」が出る
- 解禁で ! と吹き出しが出る。アップグレードタブを開くと両方消える
- 購入後は一覧から消える。並び順が「今買える」優先になる

### 開始・終了
- ページを開いた直後は、タイトル・猫・開始ボタン・ランキングだけが見える
- 開始を押すとゲーム画面に切り替わり、その上でカウントダウンが出る
- 毎回「施設タブ + まとめ買い1個 + 先頭」から始まる
- 結果画面にスコア・ベスト比較・TOP5（今回はNEW）が出る
- 「もう1回やる」は0.9秒後から押せる

### v20
- アップグレードを買ってもニュースは途中で切り替わらず、次の1本で「導入」系の見出しが流れる。ボタン位置に「導入！」
- 施設を初めて買うと、次の1本で「開業」系の見出しが流れる
- まだ持っていない施設のネタニュースが流れない
- ヒント系が3本以上続かない
- 連打しても文字が青く選択されない

### v19
- 累計スコア下の説明文が「最終得 / 点」のように途中で折り返さない
- ショップのボタンにフォーカスがあっても、スペース / Enter で猫が押され、ボタンは反応しない
- 結果画面でスペースを連打しても次のゲームが始まらない
- 結果画面を60秒放置すると待機画面に戻る。途中で触るとカウントが60に戻る
- 未確認アップグレードがあるとタブがしましまで弾む。20秒ごとに吹き出し
- スマホでは「スペース/Enter」の案内が出ない

### 残り10秒・結果
- 残り10秒から猫の上に 10〜1 が出て、終了で消える
- 結果画面に「撮影OK！」の案内が出る。PC(1280×720以上)ではスクロールなしで全体が1画面に収まる

### ねこNEWS
- 開始するとニュースが流れ始め、1本流れ終わると次に切り替わる
- 1秒3回以上の連打を続け、施設をあまり買わないと「手首を痛めて通院」系のニュースが出る
- 終了すると止まり「3分終了」表示になる

### UI
- PCで左列がスクロールしない / 右だけスクロール / タブが上に残る
- 全画像が `assets/cat.png` / 各サイズで重なり・はみ出しがない
